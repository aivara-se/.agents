# READMEs

Every application and every shared library has one at its root. It answers, in this order: what this is, how to run it locally, how to use it, how to check it.

Start from `templates/readme-template.md` and delete the guidance you did not use.

## Never

- History: where the code came from, what it replaced, how an earlier version behaved. That is the commit and the pull request.
- A roadmap, an org chart or an ADR list. The README is for the reader who runs the thing: point at the product document and stop.
- A stack list. Describe what it does, not what it is made of.

# Aivara board card delivery

A look — an operator wake naming a card on aivara-se project 2 (the Development board) — assigns one build. Carry it from Refined to an open, gate-green PR: one run per look.

A frozen spec prompt is the same loop without the card: the repository's documents are the specification, board writes are forbidden, and steps 7 and 8 do not apply. See `references/frozen-spec-delivery.md`, which also covers a design change already merged with the code to be brought up to it.

## The loop

1. **Read live state, never the prompt's snapshot:** `gh project item-list 2 --owner aivara-se --format json` (status, assignees), the card via `gh api repos/aivara-se/dispatcher/issues/<n>` (porcelain `gh issue view` can print nothing and exit 0), and the repo at `~/github/aivara-se/dispatcher` after `git pull --ff-only`.
2. Read `AGENTS.md`, `docs/PRODUCT.md`, `docs/SYSTEMS.md`, every ADR the card touches, and `~/github/aivara-se/.agents/skills/{coding,testing,writing}/SKILL.md` before writing code.
3. The card's _Frozen surface_ section is the contract: `go doc -all ./internal/<pkg>` must show nothing beyond it. Readings the card leaves open go in a PR body section named for them — never chosen in silence.
4. Parallel cards own sibling packages (check `gh pr list` for open branches); touch only what the card lists.
5. Gate before pushing, each command read: `gofmt -l .` (empty is the pass), `go vet ./...`, `go test ./...`; prove every commit green on its own tree (`git worktree add`). Boot a binary by hand: scratch config under `/root/scratch` (never `/tmp`, noexec), curl the port, SIGTERM, check exit code and files. For a package calling an outside API, run the real code read-only: copy `go.mod` and the package into `/root/scratch`, add a throwaway `cmd/` that calls it, credential in an env var — the repo stays clean, and the query checked is the one the code sends.
6. PR: title `feat: ...` in the repo's cadence; body = what changed / readings / verified (commands, SHA, real numbers) / left out, each acceptance or done-line mapped to the test that proves it, `Closes #<n>`, reviewers `thani-sh` + `thani-sh-momo`.
7. Move the card when the PR is open: `gh project item-edit 2 --owner aivara-se --url <issue url> --field Status --value Started`.
8. After the merge: verify `state,mergedAt` and the merge commit at main's tip, read the gate run on main (the Format/Vet/Test steps, not just the job), run the local gate on pulled main, then `--field Status --value Finished`. Read the board first: if it already reads Finished, no write.

## Pitfalls

- **A peer in the shared clone can undo your staged change between two commands.** One worktree serves every session, so a `git stash` or `git reset` elsewhere leaves `git status` showing staged files in one call and `git commit` answering `nothing to commit` in the next. Work in a private clone (`git clone ~/github/<org>/<repo> ~/github/<org>/<repo>-<agent>`, then `git remote set-url origin <the real URL>`), and copy `node_modules` with `cp -al` rather than a symlink: TypeScript follows the realpath and `bun run check` then fails on unmodified `main`. Before calling a branch yours, read `git log --oneline origin/<branch>` for commits you did not write, and never rewrite them.

- **A slow check outlives the terminal's timeout.** `gh pr checks <n> --watch` hangs when a runner is slow (an apt step takes minutes). Poll `gh pr checks <n>` with short sleeps and read `gh run view <id> --json jobs`; a pending status alone is not a stuck gate, and the steps running matter more than the job.
- **`item-edit` needs no field IDs** as written above; read the column back with `gh project item-list 2 --owner aivara-se --format json`. An item's `content` carries no assignees — the issue API does (`gh api repos/<owner>/<repo>/issues/<n> --jq .assignees`). For the live assignee use the repository's own board client (a `ReadAll(ctx)` adapter over `board.Client` in a scratch `cmd/`); that run is also the card's read-only live exercise: real board, printing writer and runner, nothing written.
- **A card that freezes a package's surface leaves no room for a new field.** Carry new identity in the pass's _own words_ — the decision text and the dead-letter miss reason — and record it in a named PR-body section rather than adding an export.
- **Card identity must reach the run's input.** When keys, records and writes carry the repository and number, the wake reason still collapses two cards of one number into identical words, and the reviewer reads the argv. Pin it with a test asserting the invocation line names its own card (`--profile mama chat -q "card aivara-se/dispatcher#9 …"`), and check the record that already rules on the reason rather than opening a card for it.
- **Prove a new test bites.** Put the pre-fix line back, run the one test, watch it FAIL, then `git checkout -- <path>` — restore from git, never a hand-kept copy, never leave the mutant in the tree. Judging a peer's coverage finding is the same move (`references/frozen-spec-delivery.md`).
- **`write_file` refuses an existing tracked path** ("last read with offset/limit pagination") even after a full `read_file`, because it compares against the committed blob. Rewriting a whole document is `patch` with the complete old body as `old_string` and the complete new body as `new_string`; the returned diff proves it landed.
- **A twin run shares this sandbox.** The `write_file` refusal "modified by sibling subagent" is evidence: stop editing, never patch over foreign edits. The peer may sit in another container on the same bind mount, so an empty `/proc` proves nothing. Detect it by the worktree: the card's branch carries an unpushed commit, and file mtimes and new `/root/scratch` artifacts (`dpid`/`exit.txt`, PR-body drafts, audit logs) advance as you read. Watch mtimes a minute before calling a run dead — a "no run in flight" snapshot can predate a peer mid-delivery. Then check `gh pr list --repo aivara-se/<repo>` and `git branch -a`: if a peer holds a branch or PR, your run is a duplicate — delete your unpushed leftovers, verify the peer's PR against the card's done-lines, report the twin run factually, never open a competing PR.
- **Read the item's `state` right before you write.** A twin can answer the same changes-requested review and merge while you work. If it is MERGED and the fixes are in the tree, verify and stop: drop your unpushed commit, open no competing PR; an empty `git diff --stat <reviewed head> <merge commit>` proves the merged tree is the reviewed one.
- **A tinyjs desktop app is checked by booting the build:** copy `dist/*` (`pereda` alone fails without its sibling `launcher`), `Xvfb :99`, then `DISPLAY=:99 ./pereda`; type with `xdotool windowfocus <id>` + `xdotool type` (`windowactivate` fails with no WM); click by screen coordinate read off `import -window root`; read the result with `bun:sqlite` from a copy of the app's data file plus its `-wal` (the per-launch `/tmp` dirs are not the data folder).
- **A comment or doc that conflicts with the change is deleted, not rewritten;** the map in `AGENTS.md` is fixed in the same PR it stops matching, subject to the consent note below. Never move a card another agent holds: the board is the source of truth and the service's future self writes only the assignee.
- **AGENTS.md edits can be consent-gated, and the prompt can time out.** Attempt the write once: a `patch` carrying the whole old and new body goes through on these checkouts (`aivara-se/.agents`, a repo's own root file). Only when the approval actually times out leave the file untouched and name its stale lines in the PR body — do not retry, and do not conclude the file is unwritable before trying. A timed-out gate is cleared by the operator: state the exact lines you need, and when he says to try again, re-issue the same write. No other route is permitted.
- **Work in your own clone when a peer edits the shared one.** A foreign untracked file dropped mid-run breaks the package build, so never `git add .` — commit named paths only. A peer's `git stash`/`git reset` can leave four staged files in one call and `nothing to commit, working tree clean` in the next, and a peer may commit to your branch under your name. Gate and commit in a worktree under `/root/scratch`, or clone into a private directory (`git clone ~/github/<org>/<repo> ~/github/<org>/<repo>-<agent>`, then `git remote set-url origin <the real URL>`) and symlink the original `node_modules`. `git stash push -m` dead runs' drafts with a dated message. Before claiming a branch, `git log --oneline origin/<branch>` for commits you did not write; never rewrite them — carry on top and name them.
- **A peer may have pushed the branch and opened the PR minutes after the snapshot.** Re-verify everything the body claims (gate, `-race` soak, doc citations) rather than inheriting it, fold any fix into one commit, and never force-push a public branch. As assignee you own the body: name what you found, your SHA, and what you verified.
- **`dispatcher` and `.website` allow rebase merges only** (`allow_squash_merge` and `allow_merge_commit` are false), so check `gh api .../pulls/<n> --jq '{mergeable,rebaseable}'` before claiming a PR can land: both must read true, and every branch commit must replay onto main alone. A new test placed in lines that `main` — or a parallel approved PR — also edited leaves `rebaseable: false` although the final tree would merge clean, and a later commit that moves it does not repair that. Put new tests where other changes leave them alone; re-check after every push.
- **When main moves under your branch, all your SHAs change.** Rebuild rather than hand-resolving 20+ hunks per commit: `git switch -c tmp <your head>`, `git merge --no-commit --no-ff origin/main`, resolve the one conflicting file (mechanical fixture conflicts resolve as the union — main's `boot(t, …)` with your own `card(…)`), prove `gofmt`/`vet`/`test` green, capture with `git write-tree`, reset your branch to `origin/main`, `git checkout <tree> -- .`, land one commit, and assert `git rev-parse HEAD^{tree}` equals the verified tree. Squash the reviewed round-commits in: a rebase-merge repo lands each commit. Force-push with `--force-with-lease=<ref>:<the head you are replacing>`; never rewrite a peer's branch or main.
- **Two process-tree traps.** `/proc/<pid>/environ` can read empty for a moment after a child execs, even though `cmd.Start` waits for the exec, so poll for the value; and a child that forks without exec'ing keeps its parent's `cmdline`, so require the group leader (`pgrp == pid`, from `/proc/<pid>/stat`) too. `pgrep`/`pkill -f <pattern>` also match your own shell's command line, which kills the shell (exit 143): use a pidfile or bracket the first character (`[d]ispatcher`), and kill a background server by the pid it wrote.
- **A background-mode job runs under a wrapper** (`nohup bash -lc …`) that can `cd` to `$HOME` first, and the reported pid is the wrapper's; a relative-path artifact lands beside `$HOME`. Run bounded jobs in the foreground (`cd <dir> && timeout -s TERM <n> <binary>`, read the exit code and files), or find the real child with `pgrep -x <binary>` and read by absolute path.
- **Inserting a declaration above another with `patch`:** the anchor line must appear again at the end of `new_string`. Replacing the whole `func X(` line deletes that signature and the file fails to parse one declaration later — run `gofmt -l .` on that package right after a structural patch.
- **When the directory a terminal session sits in is deleted**, every later call fails with exit 126 before the command runs. Re-issue with an explicit `workdir`.
